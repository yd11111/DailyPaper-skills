# 论文常见失败模式 / 该警觉的红旗

> 用途：精读论文时（尤其是 `批判性分析` 模式）主动扫一遍这些模式，发现命中就在锐评里点出来。
> 引用都经过 arXiv ID / URL 验证，不引用未验证的来源。

---

## 1. 引用幻觉 5 类（Adams et al. 2026）

来源：Adams, A. et al. (2026). *Compound Deception in Elite Peer Review: A Failure Mode Taxonomy of 100 Fabricated Citations at NeurIPS 2025.* arXiv:2602.05930.

| 类型 | 出现率 | 描述 | 给我们的提醒 |
|---|---|---|---|
| **Total Fabrication (TF)** | ~28% | 整篇引用是编的 — 标题/作者/期刊都不存在 | 看到陌生引用，**先用 arXiv ID / DOI 验证**再相信 |
| **Plausible Author/Conference (PAC)** | ~23% | 真学者被安上他没写过的论文 | 名字眼熟也不能跳过验证 |
| **Incomplete Hallucination (IH)** | ~19% | 没 DOI / 卷期 / 页码的"引用"高度可疑 | 在论文 reference 里没 DOI 的优先深查 |
| **Partial Hallucination (PH)** | ~18% | 真元素拼成假引用（"mashup"） | 同一引用所有字段必须对得上**同一**真实出处 |
| **Subtle Hallucination (SH)** | ~12% | 真论文+轻微篡改（错年份 / 错卷号） | 没 DOI lookup 几乎抓不到，只能凭手感警觉 |

> 100% 的样本表现出 compound（多类同时）；3-5 位 NeurIPS 评审都没看出来。给我们的教训：**别依赖直觉，懒得查的引用就标"未验证"**。

## 2. 引用准确性整体水平（Walters et al. 2023）

来源：Walters, W. H., & Wilder, E. I. (2023). *Fabrication and errors in the bibliographic citations generated by ChatGPT.* Scientific Reports, 13, 14045. https://doi.org/10.1038/s41598-023-41032-5

- GPT-3.5：**55% 引用是编的**
- GPT-4：**18% 引用是编的**
- 即使是**真实**的引用，仍有 **24-43% 含书目错误**（作者、年份、卷期、页码至少一项错）

给我们的提醒：精读论文时如果某个 baseline 你没听说过，**用 arXiv / Semantic Scholar 验一下再写入笔记的对比章节**。

## 3. 音频/语音论文专属红旗

下面是无学术引用、纯领域经验，但跟我们方向高度相关：

### 3.1 TTS 评测红旗

- **只报 MOS 不报 WER**：MOS 是主观打分（多说好听就高），但听不懂用户说什么就完了。强模型必须两个都报
- **不公开 ASR 模型**：用什么 ASR 算 WER 决定数字大小（Whisper-large-v3 / -turbo / Paraformer 结果差很多）。不写就是默认掩盖
- **不公开 speaker encoder**：算 SIM-O 用 WavLM-TDNN / ECAPA / Resemblyzer 数字相差极大
- **只在 LibriTTS 上测**：LibriTTS 太干净，泛化不可信。强模型至少要 Seed-TTS-eval / 自建复杂集
- **不报 RTF / 推理延迟**：声称 SOTA 但速度不能上线 = 学术 toy
- **零样本 TTS 不公开 prompt audio**：原参考音频质量直接决定结果，藏起来一定是挑过

### 3.2 全双工 / 对话红旗

- **不报首包延迟 (first-packet latency) / 反应时间**：「全双工」核心指标缺席就是嘴硬
- **不评估 interruption / barge-in**：模型在 demo 里能不能被打断停下来，是全双工是 vs 不是
- **只在单轮对话上测**：多轮才暴露真问题（context drift / persona 漂移）
- **没在自然对话场景测**：实验室录音 vs 真用户说话差异巨大

### 3.3 ASR 红旗

- **只在 LibriSpeech 上测**：太干净，2026 年再刷它没意义
- **不报中英混杂 / 长音频性能**：实际部署最大的两个坑
- **流式宣称但不报 chunk size / look-ahead**：用了多少未来信息直接决定能不能上线

### 3.4 Speech LLM / Audio LM 红旗

- **不和 Whisper / Qwen2-Audio / GLM-4-Voice / Moshi 这一档对比**：基线选弱了
- **只测 audio understanding 不测 audio generation**：一半能力没验
- **不报模型大小 + 训练数据规模**：「9B 端侧」「100kh+ 数据」是判断 fair compare 的前提

### 3.5 Codec / Tokenizer 红旗

- **只报 bps 不报 ViSQOL / PESQ / 重建 MOS**：压缩率高没用，要看质量
- **只在自家训练数据集上测**：codec 应该 zero-shot 重建任意音频
- **不比 EnCodec / DAC / SoundStream**：这三个是必比基线
- **声称「下游 LLM 友好」但不接 LLM 验**：嘴上说友好，实际 LM perplexity 没测

## 4. AI 写作的「同源幻觉」陷阱（Imbad0202 整理）

来源：Imbad0202/academic-research-skills 的 integrity_verification_agent.md，本身引用 Adams + Walters。

**核心警告**：如果论文是 AI 写的、你又用 AI 读，你们的训练数据高度重叠 → AI 写的"feel right"的虚假引用，AI 读的时候也会觉得"对啊我也记得"，**完全检测不出**。

给我们的提醒：精读时凡是涉及具体数字、具体 baseline 名、具体方法名的，**别用记忆验证**，老老实实 grep `audio-speech-terminology.md` 或 WebFetch 一下原始论文页。

## 5. 通用方法学红旗

- **数据集是自建且不开源**：复现不可能，结果可任意 cherry-pick
- **没有 ablation study**：哪个组件真的有用没人知道
- **训练数据量比基线大 10×**：「我赢了」可能只是数据多
- **只在自己挑的指标上赢**：先看作者**没**报告的标准指标在哪
- **图表里 y 轴 zoom 到 0.01-0.05 让差异看着大**：必看完整 y 轴
- **小模型 fair compare 大模型**：参数量没控制就别声称 SOTA
